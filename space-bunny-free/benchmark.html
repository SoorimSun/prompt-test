측정 범위와 측정하지 않은 것

숫자는 페이지 태스크 하나만 대상으로 합니다. 아래는 밝히지 않은 항목입니다.

추론하지 않은 것: 가격, 에너지, 페이지 로딩 속도. 토큰 수와 태스크 소요 시간으로는 이 중 무엇도 나올 수 없고, 어느 것도 측정하지 않았습니다. 첫 토큰까지 시간은 기록이 없어 측정 불가입니다.

토큰 산정

이 출처의 스키마가 스킬이 전정한 형태와 달라서 원본 필드를 다시 매핑했습니다. 아래 등식은 숫자를 하나라도 쓰기 전에 어시스턴트 레코드 138개 전부에 대해 확인했습니다. total = input + cache.read + output + reasoning이며, reasoning은 output과 서로 겹치지 않는 별도 스트림입니다 (레코드 30개에서 reasoning 이 output 보다 큽니다). 재매핑 후에는 스킬의 형태로, cached_input은 input 안에, reasoning_output은 output 안에 들어갑니다.

모든 값은 metrics.json → page_task 에서 재현할 수 있습니다.
필드토큰비중의미
total—100.00%input + output. 누적 처리 토큰이며 컨텍스트는 매 턴 다시 계산됩니다.
input——모델이 읽은 전체. 캐시분과 신선분을 모두 포함합니다.
  cached_input——input 의 부분집합으로 프롬프트 캐시에서 처리된 양. 반복된 컨텍스트가 여기에 쌓입니다.
  uncached_input——input − cached_input. 진짜로 새로 읽은 텍스트는 이것뿐입니다.
output——가시 출력과 reasoning 을 합친 값.
  visible_output——어시스턴트 텍스트와 도구 호출 인자.
  reasoning_output——output 의 부분집합. 출처 스토어에서는 별도 스트림입니다.
cache_write—기록 없음프롬프트 캐시 기록량. 이번 실행은 0 입니다.
검산: in + out— total 과 같아야 합니다. 확인했습니다.

총합이 아니라 캐시 비율을 보세요. — 절대 총합은 계속 커지는 컨텍스트를 반복해서 읽은 탓에 지배됩니다. 진짜로 새 자료를 얼마나 끌어들였는지를 말하는 건 캐시되지 않은 input 입니다.
